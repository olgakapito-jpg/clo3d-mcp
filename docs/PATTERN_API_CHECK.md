# Первый пакет API: лекала

Статус: **первый пакет принят для проверенной среды CLO 2026.1**:
реальная цепочка mutation/readback и bounded load10 прошли,
пользователь подтвердил визуальный эффект и отзывчивость с закрытым Script Editor.
Аватар, швы, симуляция, импорт/экспорт, изменение отдельных точек и отражение
не входят в этот пакет. Принятый транспорт P0–P3 не заменяется.

## Сравнение источника

Просмотрен `adriendelmas/clo3d-mcp-extended` revision
`df150d95db604e4651bbbdfb151b8204209a7d12`:
https://github.com/adriendelmas/clo3d-mcp-extended/tree/df150d95db604e4651bbbdfb151b8204209a7d12

В исходниках 170 MCP tools, 172 команды с ping/stop; это не 170 независимо
подтверждённых методов. Репозиторий содержит статическую проверку связности
и девять тестов файлового mock-соединения. README сообщает live-проверки
на CLO 2025.2.236 / Windows 11, не на нашей CLO 2026.1.

Полезные направления: геометрия, швы, расстановка, материалы, свойства/позы
аватара, параметры сетки, read-only документация методов. File IPC, автоматические
повторы после timeout/command error, blocking fallback listener не переносим.
Сохраняем нашу legacy-маршрутизацию `.avt` через ImportFile, `.avac` через ImportAVAC.
`MovePatternPoint` автор исключил из-за повреждения деталей, `ExportDXF` — из-за
диалога; `import_pattern_json` заменяет сцену. Эти команды не включены.

Источник — MIT, copyright Violet Sphinx / adriendelmas; LICENSE и NOTICE нужно
сохранять при копировании кода или существенных фрагментов. В этом этапе
реализован отдельный адаптер с проверкой результатов, сторонний listener
не импортируется, не устанавливается и не запускается.

## Команды и критерии

| MCP tool | Ограничение | Проверка эффекта |
| --- | --- | --- |
| list_clo_api | 5 фиксированных модулей, до 512 имён на модуль | Только список; не обещает совместимость вызовов |
| describe_clo_api | До 16 публичных имён, docstring до 8192 символов | Без вызова описываемой функции |
| get_pattern_list | До 256 деталей | Фактические индексы и имена |
| get_pattern_geometry | Один индекс | Позиция mm, площадь mm2, bounding box |
| create_pattern | 3–64 точки, простой прямолинейный контур, уникальное имя | count +1, имя, площадь по формуле многоугольника |
| set_pattern_name | Уникальное ожидаемое и новое имя | Имя, неизменные позиция/площадь/count |
| copy_pattern_with_offset | Одна копия, dx/dy mm | Возвращённый индекс, count +1, позиция, площадь, имя |
| move_pattern_relative | Перемещение целой детали, dx/dy mm | Реальный сдвиг, неизменные площадь/count |
| delete_pattern | Одна уникально именованная деталь | Полный оставшийся список имён/count |

Параметры проверяются до SDK coercion, до очереди и на стороне CLO. Нет bool
вместо int, NaN/Infinity, неизвестных полей, JSON-строки вместо списка,
самопересекающихся/нулевых/повторяющихся точек. Абсолютные координаты и сдвиги
ограничены ±100000 mm. MVP не поддерживает кривые/отверстия и большие сцены.

Перед mutation индекс сверяется с `expected_name`; дублирующиеся имена
отклоняются. Это защита от сдвинутого индекса, **не постоянный идентификатор**.
Не редактировать тестовые детали вручную во время сценария.
Создание/копирование с переименованием — несколько native вызовов, не транзакция.

Если setter уже был вызван, сбой/неудачный readback возвращает
`scene_change_unverified`, `scene_may_have_changed=True`. Нет rollback, retry
или удаления в обработчике ошибки. После `outcome_unknown` тоже сначала сверка
сцены/статуса, а не повтор команды. `command_error` не гарантирует отсутствие
побочных эффектов native API. `api_unavailable` означает, что требуемый метод
или представление геометрии в этой сборке ещё не поддерживается.

## Запуск реальной проверки

1. Остановить мост через `plugin/clo3d_mcp_stop.py`, дождаться FINISHED.
2. Закрыть и снова открыть CLO: embedded Python уже кэширует старые модули,
   простого повторного запуска launcher недостаточно для обновления кода.
3. В CLO открыть и Run `plugin/clo3d_mcp_start.py`. Закрыть Script Editor.
4. Внешний клиент сначала выполняет **только inspect**:

   `uv run --frozen python scripts/verify_patterns.py inspect`

   Предел 60 секунд; ожидается API с доступными методами, при непустой сцене
   GEOMETRY, затем PASS inspect. Это ещё не mutation acceptance.
   Перед первым созданием сверить реальные docstrings/единицы с адаптером.
5. После успешной сверки — **smoke**:

   `uv run --frozen python scripts/verify_patterns.py smoke`

   Предел 60 секунд. Создаёт асимметричную деталь площадью 7800 mm2, копирует,
   перемещает, переименовывает, независимо читает результат, удаляет только свои
   две именованные детали. Ожидается PASS с `scene_list_restored=True`.
6. Только после принятия smoke — **load**:

   `uv run --frozen python scripts/verify_patterns.py load`

   Предел 180 секунд, 10 циклов copy/move/name/delete и независимые чтения;
   одновременно не более двух тестовых деталей, не более 256 всего.
   Не 30-минутный soak и не проверка аватара/симуляции или большой сетки.
   Пользователь отдельно подтверждает отзывчивость CLO с закрытым редактором.

Все обращения идут через настоящий HTTP MCP и Named Pipe, без файла IPC,
экспортов и повтора команд. Клиент не запускает/не останавливает CLO.
Остановка: Ctrl+C во внешнем клиенте прекращает новые шаги, **не прерывает**
отправленную native-команду. Мост останавливается `plugin/clo3d_mcp_stop.py`.
При ошибке клиент не продолжает автоматическую очистку, а оставляет детали
для сверки по уникальному префиксу `mcp_test_...` из START.

Отказ: отсутствующий метод, неизвестная форма geometry record, неверные единицы,
несовпадение площади/сдвига/count, timeout, dialog, quarantine, изменение сеанса,
ошибка статуса или зависание UI. Остановить сценарий и диагностировать,
не повышать deadlines и не воспроизводить mutation автоматически.

## Измерения и границы доказательств

- `executor_ms`: preflight + setter(s) + readback в UI callback, НЕ чистое
  время native setter. Чтение/сериализация вне этого интервала отдельно не измерены.
- latency: полный MCP round trip с ожиданием очереди; p95/max выводит клиент.
- Время ожидания очереди отдельно пока не инструментировано.
- Восстановление списка имён не доказывает побитовую идентичность всей сцены.
- Успешный небольшой сценарий доказывает ограниченные операции с лекалами,
  а не тяжёлую симуляцию/аватар. Это следующие отдельные пакеты.

Локальные unit/HTTP/Windows fake-API результаты и фактический CLO результат
фиксируются по завершении; не считать mocks основанием закрыть real-CLO gate.

### Первый реальный inspect и исправление формата

После свежего запуска получен ready-сеанс `b6b9c5d9fc034eea14be330760fa82d8`,
CLO PID12872, MCP PID17792, весь первый пакет в capabilities.
`uv run --frozen python scripts/verify_patterns.py inspect` завершён PASS:
все десять необходимых методов доступны, список деталей пуст. Это проверка
доступности/docstrings, **не чтение геометрии существующей детали**.

Реальная сигнатура `GetBoundingBoxOfPattern(int) -> Dict[str, str]` выявила
несовместимость адаптера до первой mutation. `_box` теперь сохраняет ограниченные
строковые поля native-словаря, не угадывая их числовое представление/единицы.
Числовые position/area проверяются отдельно. Добавлены регрессионные проверки
формата и отказа на oversized/invalid значения. Имена ключей/содержимое настоящего
bounding box пока не наблюдались: сцена пустая, тестовые поля синтетические.

После исправления focused **60 passed**, полная suite **306 passed**, без skips.
Отдельный readback списка подтвердил count0; status того же сеанса ready,
waiting0, active=None, quarantine=False, error=None. Изменяющие команды
**не отправлялись**, smoke/load не запускались. Исправление ещё не загружено
во встроенный Python: требуется свежий CLO + обновлённый launcher, затем
проверка первого создания/readback без автоматического повтора при ошибке.
